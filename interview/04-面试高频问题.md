# 04 — Agent 面试高频问题

基于 2026 年字节/阿里/腾讯真实面经整理。

---

## Q1: 你的 Agent 怎么设计的？

**错误回答**：『用了 LangGraph + Function Calling』

**正确回答**：

> "复杂问题用 Plan-and-Execute 模式：LLM 先 decompose 拆成子问题，orchestrator 按依赖顺序执行，
> Reflection 检查结果并标记依赖断裂。SQL 执行失败时 ReAct Agent 接管，
> 用 OpenAI Function Calling 自主选择工具修复，最多 3 轮尝试。
> 三种 Agent 范式组合覆盖规划-执行-修复的完整环。"

---

## Q2: ReAct 和 Plan-Execute 的区别？为什么都用了？

**回答**：

> "ReAct 适合小范围、不确定性的修复——每次执行完看结果再决定下一步。
> Plan-Execute 适合目标明确的复杂查询——先想清楚再执行，效率更高。
> 两个同时用是因为不同阶段需求不同：规划阶段要效率，修复阶段要灵活性。"

---

## Q3: 你的 Agent 失败/中断了怎么办？

**回答**：

> "三个层面的处理：
> 1. 单个 SQL 失败 → ReAct Agent 自主修复，最多 3 轮
> 2. 修复失败 → Reflection 检查依赖链，标记后置步骤为'跳过'
> 3. 汇总时 LLM 看到完整失败上下文，如实告知用户失败原因
> 不是无声崩溃，用户能看到所有失败信息和原因。"

---

## Q4: Function Calling 和手写 action 匹配有什么区别？

**回答**：

> "手写匹配是字符串 if-else——LLM 返回 `{"action":"xxx"}`，
> 代码手动匹配。LLM 拼错一个字就挂了。
> Function Calling 是 API 层的原生能力——工具名和参数 schema
> 在 API 层被校验，LLM 不可能调用不存在的工具或漏必需参数。
> 我们最初是手写匹配，后来升级到 Function Calling，
> 可靠性显著提升。"

---

## Q5: 你的 RAG 怎么做的？召回率多少？

**回答**：

> "Schema RAG：用表名+字段名+类型+样本值自动构建 embedding 文本，
> 启动时批量向量化存内存。查询时余弦相似度打分，
> 两阶段检索（先筛表、再筛字段、表命中加权）。
> 11 张表时开启/关闭 RAG 准确率不变（76.7%），
> 验证了筛选策略不会误伤关键表。扩展到大库时预估节省 60%+ Token。"

---

## Q6: Bad Case 有哪些？怎么修的？

**回答**：

> "主要是三类：
> 1. SELECT * 问题 → 加了 prompt 强约束 + Few-shot 示例
> 2. LEFT JOIN 误用 → prompt 加了'默认 INNER JOIN'规则
> 3. 字段含义不明确（Milliseconds）→ Few-shot 示例展示换算逻辑
> 每题都有根因分析和前后对比。"

---

## Q7: 最难的技术点是什么？

**回答**：

> "Schema RAG 的召回率和 SQL 校验精度的平衡。
> 召回太宽 Token 浪费，太严缺字段导致 SQL 被拒。
> 最后用了入选表全字段保留的策略，既保证了校验通过率，又过滤了无关表。"

---

## Q8: 为什么用 LangGraph 而不是 LangChain 的 Chain？

**回答**：

> "LangGraph 的 StateGraph 天然支持条件路由和状态管理。
> 我的系统有分支（simple/complex 走不同路）、
> 有循环（ReAct Repair 可以 route 回 execute）、
> 有状态（35+ 字段的 Text2SQLState）。Chain 是线性的，做不了这些。"

---

## Q9: MCP 了解吗？和 Function Calling 什么区别？

**回答**：

> "MCP 是跨进程的工具共享协议——你做了一个工具，别人的 AI 也能通过协议发现和调用。
> Function Calling 是进程内的工具调度——Agent 用自己的工具。
> 我的 ReAct Repair 用 Function Calling 就够了，
> 工具都是系统内部的。MCP 适合面向外部生态的工具发布场景。"

---

## Q10: 多轮对话和记忆怎么做的？

**诚实回答**：

> "当前是一问一答模式。后续计划加入基于 Session 的对话历史管理，
> 支持追问、纠错和下钻。LangGraph 的 checkpoint 机制天然适合做这个——每次 state 变化都有快照。"
