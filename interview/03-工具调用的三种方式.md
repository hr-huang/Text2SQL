# 03 — 工具调用的三种方式

你纠结了很久的 LangChain Tool / Function Calling / MCP，本质区别就一个：**工具定义和 LLM 之间隔着什么。**

---

## 方式 1：硬编码 Action 字符串（你现在不用了）

```python
# LLM 返回普通 JSON
{"action": "schema_lookup", "input": {"table_name": "customers"}}

# 代码手动匹配
if action_name == "schema_lookup":      # ← 如果 LLM 写成 "Schema_Lookup" 就匹配失败
    tool.run()
elif action_name == "rewrite_sql":
    ...
```

**问题**：LLM 可能拼错 action 名、漏参数、造不存在的 action。没有校验层。

---

## 方式 2：Function Calling（你现在用的）

```python
# 工具定义（OpenAI 标准格式）
tools = [{
    "type": "function",
    "function": {
        "name": "schema_lookup",
        "description": "查询某张表的字段结构",
        "parameters": {
            "type": "object",
            "properties": {
                "table_name": {"type": "string", "description": "要查询的表名"}
            },
            "required": ["table_name"]
        }
    }
}]

# 调 LLM 时传进去
response = client.chat.completions.create(
    model="deepseek-v4-flash",
    messages=[...],
    tools=tools,
    tool_choice="auto"
)

# LLM 返回的不是文本，是 tool_call
response.choices[0].message.tool_calls[0]
# → {"function": {"name": "schema_lookup", "arguments": '{"table_name":"customers"}'}}
# API 层保证了: 名字不会拼错、参数格式一定对
```

**解决**：API 层校验工具名和参数，LLM 不可能调用不存在的工具。

---

## 方式 3：LangChain Tool（你没用，也不需要）

```python
from langchain.tools import Tool

schema_lookup_tool = Tool(
    name="schema_lookup",
    func=lambda table_name: SchemaLookupTool().run(table_name=table_name),
    description="查询某张表的字段结构"
)

# 效果和 Function Calling 一样，多了一层 LangChain 封装
```

**为什么不需要**：Function Calling 是 API 原生能力，LangChain Tool 在上面包了一层抽象。你的场景里没有额外受益——LangChain Tool 的组合/链式调用/回调这些功能你用不上。

---

## 方式 4：MCP（你的内部工具不需要）

```
MCP = 工具定义在独立进程里，通过标准协议通信
```

```
Function Calling:                    MCP:
  LLM ←→ 你的代码 ←→ 工具             LLM ←→ MCP 协议 ←→ 另一个进程(工具)
  (同一个进程)                         (进程间通信)
```

**适用场景**：
- ✓ 你做了一个工具，想让别人的 AI 也能用 → MCP
- ✗ 你自己的 Agent 用自己的工具 → Function Calling

**你的场景是后者**——ReAct Repair 的工具（schema_lookup / execute_sql）是你系统内部的，永远不需要给别人用。

---

## 你的项目：方式 2（Function Calling）

**面试时**：

> "ReAct Repair Agent 使用 OpenAI 原生 Function Calling 做工具调度。
> 四个工具的 JSON Schema 定义和 LLM API 调用的 tools 参数，
> API 层保证工具名和参数格式不会出错。
> 没有用 LangChain Tool 包装，因为 Function Calling 更底层、更可控，
> 少一层依赖就少一个可能出问题的地方。"

---

## 总结

| | 适合场景 | 你的项目 |
|------|---------|---------|
| 硬编码 | 工具固定、自己玩 | ✗ 已升级 |
| Function Calling | LLM 自己的工具 | ✓ ReAct Repair |
| LangChain Tool | 需要链式、回调 | ✗ 不需要 |
| MCP | 跨进程/跨 AI 共享工具 | ✗ 不需要 |
